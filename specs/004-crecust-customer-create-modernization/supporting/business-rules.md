# Business Rules - CRECUST Customer Create Modernization

**Document ID:** `business-rules.md`  
**Authority:** CRECUST.cbl + CRECUST.cpy + CUSTOMER.cpy + CUSTDB2.cpy

## Rule Catalog

### BR-001 Title Allowlist
- Statement: `title` must match one of legacy-accepted values.
- Allowed: `Professor`, `Mr`, `Mrs`, `Miss`, `Ms`, `Dr`, `Drs`, `Lord`, `Sir`, `Lady`, blank.
- Failure: set legacy fail code `T`.

### BR-002 System Sortcode
- Statement: Sortcode is system-derived from legacy constant source (`SORTCODE`) and not accepted from API client.

### BR-003 Credit Score Orchestration
- Statement: Credit score is obtained through multi-source orchestration (legacy async model); modern POC uses adapter simulation with equivalent output semantics.
- Success path: average score across responders.
- Failure/no data path: score `0` and fallback review date behavior.

### BR-004 DOB Minimum Year
- Statement: DOB year must be >= 1601.
- Failure code: `O`.

### BR-005 DOB Calendar Validity
- Statement: DOB must be a valid calendar date.
- Failure code: `Z`.

### BR-006 DOB Not Future
- Statement: DOB cannot be later than today.
- Failure code: `Y`.

### BR-007 DOB Max Age
- Statement: Derived age must be <= 150.
- Failure code: `O`.

### BR-008 Customer Number Allocation
- Statement: Next customer number is generated by incrementing sortcode-scoped control value.
- Failure code: `4` when control read/update fails.

### BR-009 Customer Persistence
- Statement: Customer record is persisted with eyecatcher `CUST` and integer dates (`YYYYMMDD`) for date-of-birth, created-date, and credit-review-date.
- Failure code: `1` when create write fails.

### BR-010 Counter Locking Semantics
- Statement: Legacy enqueue/dequeue control semantics are preserved logically for sequence consistency.
- Failures:
  - enqueue failure -> `3`
  - dequeue failure -> `5`

### BR-011 Credit Orchestration Fail Codes
- Fail codes retained from legacy flow:
  - `A` PUT CONTAINER failed
  - `B` RUN child transaction failed
  - `C` FETCH ANY not-finished/no data
  - `D` FETCH ANY invalid request/no children
  - `E` GET CONTAINER failed
  - `F` child completion ABEND
  - `G` credit fallback failure/general credit-check error
  - `H` unknown completion status

### BR-012 Success Signaling
- Statement: On successful create, response carries `commSuccess=Y` and blank fail code.

### BR-013 Error Signaling
- Statement: On failed create, response carries `commSuccess=N` and the mapped fail code.

## Fail Code Mapping Table

| Fail Code | Source Condition | Modern Meaning |
|---|---|---|
| `T` | Invalid title | Business validation failed |
| `O` | DOB year<1601 or age>150 | DOB outside acceptable range |
| `Z` | Invalid DOB format/date | DOB invalid |
| `Y` | DOB in future | DOB invalid |
| `1` | Insert CUSTOMER failed | Persistence write failure |
| `3` | ENQ failure | Lock/control acquisition failure |
| `4` | CONTROL select/update failure | Number-generation state failure |
| `5` | DEQ failure | Lock/control release failure |
| `A`-`H` | Credit orchestration failures | Credit subsystem failure variants |
