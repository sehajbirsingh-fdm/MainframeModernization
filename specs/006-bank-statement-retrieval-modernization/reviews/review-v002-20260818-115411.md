## Findings

### MAJOR-001: Mapping Matrix And Data Model Require Period Boundaries Not Present In API Contract

- Evidence: Mapping defines `summary.periodFrom` and `summary.periodTo` at `supporting/mapping-matrix.md:7` and `supporting/mapping-matrix.md:8`; data model defines `StatementPeriod.periodFrom/periodTo` at `data-model.md:9` and `data-model.md:10`; OpenAPI summary schema at `contracts/openapi.yaml:73`-`contracts/openapi.yaml:81` does not expose period boundary fields.
- Why it matters: Spec-to-contract inconsistency creates implementation ambiguity and test drift; teams cannot know whether period boundaries must be returned.
- Suggested fix: Decide one contract shape and align all artifacts. Either add boundary fields to response schema (and tests) or remove them from mapping/data-model if intentionally internal.
- Recommended owner: Dev Lead

### MAJOR-002: Period Validation Is Under-Specified At API Boundary

- Evidence: `period` is constrained only by regex `^[0-9]{6}$` in `contracts/openapi.yaml:26`, while requirements say enforce statement month semantics (`spec.md:33`, `supporting/requirements.md:5`).
- Why it matters: Values like `202613` and `202600` satisfy the current schema but are invalid months; this is a boundary-validation gap for a core business input.
- Suggested fix: Strengthen period validation semantics (e.g., month range `01..12`) in contract and add explicit negative tests for invalid month values.
- Recommended owner: Dev

### MAJOR-003: Constitution Scope Conflict With Feature 006 Not Explicitly Governed

- Evidence: Constitution scope is bounded to INQCUST customer inquiry at `.specify/memory/constitution.md:11`-`:13`; Feature 006 introduces BNKSTMT-based statement retrieval at `spec.md:1` and `spec.md:7`-`:8`.
- Why it matters: Governance conflict can block approval and introduce policy ambiguity during implementation and review.
- Suggested fix: Add an explicit constitution exception or update constitution scope through approved governance process before implementation proceeds.
- Recommended owner: Product
