# Requirements Quality Checklist

## Spec Completeness

- [ ] Feature overview explains who the feature is for and why it exists.
- [ ] Scope and non-goals are explicit.
- [ ] Functional requirements are numbered and testable.
- [ ] Business rules are numbered and testable.
- [ ] Positive scenarios are included.
- [ ] Negative scenarios are included.
- [ ] Edge cases are included.
- [ ] Error codes and statuses are defined.
- [ ] OpenAPI contract exists.
- [ ] Mapping matrix exists.
- [ ] Mock integration boundary is clear.
- [ ] No behavior requires access to real mainframe infrastructure.

## AI Readiness

- [ ] Copilot can implement without guessing fields.
- [ ] DTOs are defined.
- [ ] Repository contract is defined.
- [ ] Tests can be generated directly from scenarios.
- [ ] Forbidden implementation choices are documented.

## Review Outcome

- [ ] PASS
- [ ] FAIL - requires clarification
